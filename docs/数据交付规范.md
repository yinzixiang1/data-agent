# NL2SQL 语义层数据交付规范

**给数仓/业务同学的填写指南**

> DDL 和列类型系统会自动从 Doris 抓取，不需要你手动提供。
> 你只需要提供**机器拿不到的业务知识**。

---

## 需要提供什么

共 4 份材料（对应 MySQL `data_agent` 库的表）：

| # | 材料 | 一句话说明 | 谁来填 | 对应 MySQL 表 |
|---|------|-----------|--------|--------------|
| 1 | **表信息 + 列补充** | 每张表的中文名、用途、列的枚举值 | 数仓 | `da_table` + `da_table_column` |
| 2 | **业务术语表** | 业务名词→计算口径/过滤条件 | 业务+数仓 | `da_glossary` |
| 3 | **常见问题 & 标准 SQL** | 用户经常问的问题 + 对应的正确 SQL | 数仓 | `da_fewshot` / `da_table_query` |
| 4 | **表关联关系**（可选） | 表之间的 JOIN 关系 | 数仓 | `da_table_relation` |

---

## 材料 1：表信息登记

每张需要接入的表填一行。

### 字段说明

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| name | 是 | Doris 表名 | pmt_account |
| database_name | 否 | 数据库名（默认 dwd_banking） | dwd_banking |
| display_name | 是 | **中文表名** | 商户账户表 |
| description | 是 | **这张表干什么的**，2-3 句话 | 支付系统的核心账户表，记录所有商户/个人的账户信息 |
| tags | 是 | 业务标签，JSON 数组，用于检索 | ["账户", "商户", "KYC", "风险"] |
| query_tips | 否 | **查这张表需要注意什么** | 查询时需带 is_delete=0 过滤已删除记录 |

### 填写示例

```
name:           pmt_account
display_name:   商户账户表
description:    支付系统的核心账户表，记录所有商户/个人的账户信息，
                包含基本信息、法人实体、KYC认证状态、风险评级、账户状态等。
                每行代表一个独立账户。
tags:           ["账户", "商户", "KYC", "风险", "支付", "开户"]
query_tips:     查询时需带 is_delete=0 过滤已删除记录
```

### 列补充信息

DDL 里的 COMMENT 如果已经写清楚了，这部分可以不填。**只需要补充 DDL COMMENT 里没写清楚的列**。

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| name | 是 | 列名 | account_type |
| display_name | 否 | 中文列名 | 账户类型 |
| description | 否 | 补充说明 | 区分不同商户角色 |
| enum_values | 否 | **枚举值含义**（最重要） | [{"value": 1000, "label": "普通账户"}, {"value": 2000, "label": "LPSP"}] |
| business_logic | 否 | 业务逻辑/计算方式 | 退货率 = 退货订单数/总订单数 |
| sensitive | 否 | 是否敏感字段 | true（identification_value 是证件号码） |
| skip_index | 否 | 是否跳过索引 | true（metadata 是 JSON 元数据） |

### 列补充的填写示例

```
column:          account_type
display_name:    账户类型
enum_values:     [{"value": 1000, "label": "普通账户"}, {"value": 2000, "label": "LPSP"}, {"value": 2001, "label": "TPSP"}, {"value": 3000, "label": "RPSP"}]

column:          verification_status
display_name:    KYC/KYB认证状态
enum_values:     [{"value": -1, "label": "拒绝"}, {"value": 0, "label": "默认"}, {"value": 1, "label": "已通过"}, {"value": 2, "label": "审核中"}]

column:          identification_value
sensitive:       true（证件号码，不参与检索和 Prompt）

column:          metadata
skip_index:      true（JSON 元数据，用户不会查）
```

## 材料 2：业务术语表

把业务里常用的名词/缩写/黑话整理出来。**这是对 SQL 准确率影响最大的一份材料**。

### 字段说明

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| term | 是 | 术语/名词 | KYC通过率 |
| definition | 是 | **用大白话解释是什么** | KYC认证通过的账户数占总账户数的比例 |
| sql_hint | 否 | **对应的 SQL 写法**（写了效果最好） | COUNT(CASE WHEN verification_status=1 THEN 1 END) / COUNT(*) |
| related_tables | 否 | 涉及哪些表（JSON 数组） | ["pmt_account"] |
| related_columns | 否 | 涉及哪些列（JSON 数组） | ["pmt_account.verification_status"] |

### 填写示例

```
term:             活跃商户
definition:       account_status = 1 且 is_delete = 0 的账户
sql_hint:         account_status = 1 AND is_delete = 0
related_tables:   ["pmt_account"]
related_columns:  ["pmt_account.account_status", "pmt_account.is_delete"]

term:             LPSP
definition:       License Payment Service Provider，持牌支付服务商
sql_hint:         account_type = 2000
related_tables:   ["pmt_account"]
related_columns:  ["pmt_account.account_type"]

term:             高风险商户
definition:       风险等级为 HIGH 或 VERY_HIGH 的商户
sql_hint:         risk_rating_level IN ('HIGH', 'VERY_HIGH')
related_tables:   ["pmt_account"]
related_columns:  ["pmt_account.risk_rating_level"]
```

### 容易遗漏的术语类型

| 类型 | 举例 |
|------|------|
| **缩写/英文简称** | LPSP、TPSP、RPSP、MCC、KYC、KYB、GMV |
| **状态码含义** | verification_status=1 到底是什么意思 |
| **计算指标** | 通过率、转化率、退货率的分子分母分别是什么 |
| **区域/分组映射** | "华东区"包含哪些省份、"大客户"的定义门槛 |
| **时间默认值** | "最近"默认指多久、"上个月"是自然月还是滚动30天 |
| **过滤条件** | 查询时哪些条件是默认要带的（is_delete=0、status!=cancelled） |

## 材料 3：常见问题 & 标准 SQL

收集用户**真实会问的问题**，配上正确的 SQL。这些会作为 Few-shot 示例直接喂给 AI。

### 字段说明

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| question | 是 | **用户会怎么问**（口语化） | 目前有多少活跃商户 |
| sql | 是 | **正确的 SQL**（必须可执行） | SELECT COUNT(*) ... |
| tables | 是 | 涉及哪些表（JSON 数组） | ["pmt_account"] |
| difficulty | 否 | 难度：easy / medium / hard | easy |

### 填写示例

```
question:    目前有多少活跃商户
tables:      ["pmt_account"]
difficulty:  easy
sql: |
  SELECT COUNT(*) AS "活跃商户数"
  FROM dwd_banking.pmt_account
  WHERE account_status = 1
    AND is_delete = 0

question:    KYC认证通过率是多少
tables:      ["pmt_account"]
difficulty:  medium
sql: |
  SELECT
    COUNT(CASE WHEN verification_status = 1 THEN 1 END) AS "已通过",
    COUNT(*) AS "总数",
    ROUND(COUNT(CASE WHEN verification_status = 1 THEN 1 END) / COUNT(*) * 100, 2) AS "通过率(%)"
  FROM dwd_banking.pmt_account
  WHERE is_delete = 0

question:    各国家的商户数量分布
tables:      ["pmt_account"]
difficulty:  easy
sql: |
  SELECT country AS "国家", COUNT(*) AS "商户数"
  FROM dwd_banking.pmt_account
  WHERE is_delete = 0
  GROUP BY country
  ORDER BY COUNT(*) DESC
  LIMIT 100

question:    各账户类型的商户占比
tables:      ["pmt_account"]
difficulty:  medium
sql: |
  SELECT
    CASE account_type
      WHEN 1000 THEN '普通账户'
      WHEN 2000 THEN 'LPSP'
      WHEN 2001 THEN 'TPSP'
      WHEN 3000 THEN 'RPSP'
      ELSE '其他'
    END AS "账户类型",
    COUNT(*) AS "数量",
    ROUND(COUNT(*) / SUM(COUNT(*)) OVER() * 100, 2) AS "占比(%)"
  FROM dwd_banking.pmt_account
  WHERE is_delete = 0
  GROUP BY account_type
  ORDER BY COUNT(*) DESC

question:    高风险商户有哪些，列出名称和国家
tables:      ["pmt_account"]
difficulty:  medium
sql: |
  SELECT
    account_name AS "商户名",
    legal_entity_name AS "企业名称",
    country AS "国家",
    risk_rating_level AS "风险等级",
    risk_score AS "风险评分"
  FROM dwd_banking.pmt_account
  WHERE risk_rating_level IN ('HIGH', 'VERY_HIGH')
    AND is_delete = 0
  ORDER BY risk_score DESC
  LIMIT 100
```

### SQL 书写规范

- 必须是可直接执行的 **Doris SQL**
- 列别名用中文双引号：`COUNT(*) AS "数量"`
- 枚举值查询用 CASE WHEN 翻译成中文
- Doris 日期函数注意：`DATE_TRUNC(datetime, 'unit')` 不是 `DATE_TRUNC('unit', datetime)`
- difficulty：单表简单聚合 = easy，CASE WHEN/多条件 = medium，多表 JOIN/窗口函数 = hard

### 每张表建议覆盖的问题类型

| 类型 | 示例 | 每张表至少 |
|------|------|-----------|
| 简单计数 | "有多少XX" | 2 条 |
| 分组统计 | "按XX分布" | 2 条 |
| 比率/占比 | "XX率是多少" | 1 条 |
| 条件筛选 | "满足XX条件的有哪些" | 1 条 |
| 时间范围 | "最近XX天/上个月" | 1 条 |
| 多表 JOIN | "XX关联YY查询" | 1 条（如有关联表） |
| 排序/TOP N | "排名前10的XX" | 1 条 |

**每张表建议 8-15 条问题，覆盖以上类型。**

## 材料 4（可选）：表关联关系

如果多张表之间有 JOIN 关系，请整理出来。

### 字段说明

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| column_name | 是 | 本表关联列 | customer_id |
| target_table | 是 | 目标表 | dim_customer |
| target_column | 是 | 目标表关联列 | customer_id |
| join_type | 否 | JOIN 方式（默认 LEFT JOIN） | LEFT JOIN |

### 填写示例

```
table:           pmt_account
column_name:     customer_id
target_table:    dim_customer
target_column:   customer_id
join_type:       LEFT JOIN

table:           pmt_finance_transactions
column_name:     account_id
target_table:    pmt_account
target_column:   account_id

```

## 交付格式

以下任一格式均可：

| 格式 | 适合场景 |
|------|---------|
| **Excel**（推荐） | 最方便填写，一个 Sheet 一份材料 |
| **CSV** | 导出方便 |
| **飞书/Notion 表格** | 在线协作 |

收到后通过管理后台（dataAgent-admin-api）录入 MySQL `data_agent` 库，重启服务自动生效。

> 不需要一次交齐。可以先给 3-5 张核心表，系统跑起来后再逐步补充。

## 优先级建议

如果时间紧，按以下优先级准备：

```
P0（必须有，否则系统跑不起来）
  ├── 表信息：display_name + description + tags
  └── 常见问题 & 标准 SQL：每张表至少 5 条

P1（强烈建议，显著提升准确率）
  ├── 业务术语表：缩写、状态码含义、计算指标
  └── 列枚举值：enum_values 补全

P2（锦上添花）
  ├── 表关联关系
  ├── 列级补充（display_name、sensitive、skip_index）
  └── 每张表补到 10-15 条问题
```

## 用 Claude 辅助生成

### Step 1: 扫描业务代码

在业务项目的代码仓库中，让 Claude 先扫描代码，提取与目标表相关的信息：

````
请扫描当前项目代码，提取与表 `<表名>` 相关的以下信息：

1. **枚举定义** — Java/Python/TS 的 enum 类、常量类
2. **查询模式** — 常见 WHERE 条件、GROUP BY、JOIN
3. **业务术语** — 代码注释、Swagger 中的中文描述
4. **敏感字段** — 有脱敏/加密处理的字段

整理为结构化表格输出。
````

### Step 2: 导出建表 DDL

```sql
SHOW CREATE TABLE <表名>;
```

### Step 3: 让 Claude 生成材料

将代码分析结果 + DDL 一起喂给 Claude：

````
根据以下「代码分析结果」和「建表 DDL」，按照下面的格式生成 4 份材料。

要求：
1. 枚举值优先使用代码中的定义（比 DDL COMMENT 更完整）
2. 中文名优先用代码注解/i18n 中的中文
3. SQL 必须可在 Doris 上直接执行
4. tags 包含：中文关键词 + 业务术语 + 用户可能的口语表达

材料格式参考本文档中的模板。

代码分析结果：
<粘贴 Step 1 的输出>

建表 DDL：
```sql
<粘贴 SHOW CREATE TABLE 输出>
```
````

### Step 4: 人工审核

| 审核项 | 重点 |
|--------|------|
| **enum_values** | 对照代码枚举类，确认值和 label 完全一致 |
| **relations** | 确认 target_table 和 target_column 正确 |
| **SQL** | 在 Doris 上跑一遍确认可执行 |
| **sensitive** | 对照公司数据安全规范 |
| **tags** | 补充团队内部黑话/缩写 |

## 附：MySQL 表结构参考

数据存入 MySQL `data_agent` 库，由 dataAgent-admin-api 管理。以下是各表的核心字段：

### da_table（表语义）

| 字段 | 类型 | 说明 |
|------|------|------|
| name | VARCHAR(128) | 表名（唯一） |
| database_name | VARCHAR(64) | 数据库名 |
| display_name | VARCHAR(128) | 中文名 |
| description | TEXT | 表描述 |
| tags | TEXT | 标签 JSON 数组 |
| query_tips | VARCHAR(512) | 查询注意事项 |
| status | SMALLINT | 1=启用 0=禁用 |

### da_table_column（列语义）

| 字段 | 类型 | 说明 |
|------|------|------|
| table_id | INT | 所属表 ID（FK → da_table.id） |
| name | VARCHAR(128) | 列名 |
| display_name | VARCHAR(128) | 中文名 |
| description | TEXT | 描述 |
| enum_values | TEXT | 枚举值 JSON 数组 |
| business_logic | TEXT | 业务逻辑 |
| sensitive | BOOLEAN | 是否敏感 |
| skip_index | BOOLEAN | 是否跳过索引 |

### da_table_relation（表关联）

| 字段 | 类型 | 说明 |
|------|------|------|
| table_id | INT | 所属表 ID（FK → da_table.id） |
| column_name | VARCHAR(128) | 本表关联列 |
| target_table | VARCHAR(128) | 目标表名 |
| target_column | VARCHAR(128) | 目标列名 |
| join_type | VARCHAR(32) | JOIN 类型 |

### da_glossary（业务术语）

| 字段 | 类型 | 说明 |
|------|------|------|
| term | VARCHAR(128) | 术语（唯一） |
| definition | TEXT | 定义 |
| sql_hint | VARCHAR(512) | SQL 条件 |
| related_tables | TEXT | 关联表 JSON 数组 |
| related_columns | TEXT | 关联列 JSON 数组 |
| status | SMALLINT | 1=启用 0=禁用 |

### da_fewshot（全局 Few-shot）

| 字段 | 类型 | 说明 |
|------|------|------|
| question | VARCHAR(1024) | 问题 |
| sql | TEXT | SQL |
| tables | VARCHAR(512) | 涉及的表 JSON 数组 |
| difficulty | VARCHAR(16) | 难度 |
| status | SMALLINT | 1=启用 0=禁用 |

### da_table_query（表级常见问题）

| 字段 | 类型 | 说明 |
|------|------|------|
| table_id | INT | 所属表 ID（FK → da_table.id） |
| question | VARCHAR(512) | 问题 |
| sql | TEXT | SQL |
| tables | VARCHAR(512) | 涉及的表 JSON 数组 |
| difficulty | VARCHAR(16) | 难度 |

### da_enum_def + da_enum_value（枚举字典）

**da_enum_def:**

| 字段 | 类型 | 说明 |
|------|------|------|
| table_name | VARCHAR(128) | 所属表名 |
| field_name | VARCHAR(128) | 字段名 |
| field_label | VARCHAR(128) | 字段标签 |

**da_enum_value:**

| 字段 | 类型 | 说明 |
|------|------|------|
| definition_id | INT | 枚举定义 ID（FK → da_enum_def.id） |
| code | VARCHAR(64) | 枚举码值 |
| label | VARCHAR(128) | 英文标签 |
| label_cn | VARCHAR(128) | 中文标签 |
| sort_order | INT | 排序 |

> 表结构由 dataAgent-admin-api 管理，DDL 见该项目的 ORM 模型定义。
