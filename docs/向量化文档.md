# 数据交付规范

**给数仓/业务同学的填写指南**

> DDL 和列类型系统会自动从 Doris 抓取，不需要你手动提供。
> 你只需要提供**机器拿不到的业务知识**。

---

## 

共 3 份材料：

| # | 材料 | 一句话说明 | 谁来填 |
|---|------|-----------|--------|
| 1 | **表信息登记表** | 每张表的中文名、用途、注意事项 | 数仓 |
| 2 | **业务术语表** | 业务名词→计算口径/过滤条件 | 业务+数仓 |

## 材料 1：表信息登记表

每张需要接入的表填一行。

### 模板（Excel / CSV）

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| database | 是 | Doris 库名 | dwd_banking |
| table_name | 是 | 表名 | pmt_account |
| display_name | 是 | **中文表名**（用户能理解的名字） | 商户账户表 |
| description | 是 | **这张表是干什么的**，2-3 句话 | 支付系统的核心账户表，记录所有商户/个人的账户信息，包含基本信息、法人实体、KYC状态、风险评级等 |
| tags | 是 | 业务标签，逗号分隔，用于检索 | 账户,商户,KYC,风险,支付,开户 |
| owner | 否 | 表负责人 | 张三 |
| update_frequency | 否 | 更新频率 | 实时 / 每日 / 每小时 |
| query_tips | 否 | **查这张表需要注意什么**（非常重要） | 查询时需带 is_delete=0 过滤已删除记录 |

### 填写示例

```
database:          dwd_banking
table_name:        pmt_account
display_name:      商户账户表
description:       支付系统的核心账户表，记录所有商户/个人的账户信息，
                   包含基本信息、法人实体、KYC认证状态、风险评级、账户状态等。
                   每行代表一个独立账户。
tags:              账户,商户,KYC,风险,支付,开户
query_tips:        查询时需带 is_delete=0 过滤已删除记录
```

### 附加：列补充信息（可选但强烈建议）

DDL 里的 COMMENT 如果已经写清楚了，这部分可以不填。**只需要补充 DDL COMMENT 里没写清楚的列**。

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| table_name | 是 | 所属表 | pmt_account |
| column_name | 是 | 列名 | account_type |
| display_name | 否 | 中文列名（COMMENT 不清楚时补充） | 账户类型 |
| enum_values | 否 | **枚举值含义**（最重要，COMMENT 里经常写不全） | 1000=普通账户, 2000=LPSP, 2001=TPSP, 3000=RPSP |
| business_logic | 否 | 业务逻辑/计算方式 | 退货率 = 退货订单数/总订单数 |
| sensitive | 否 | 是否敏感字段（不应出现在查询结果中） | 是 — identification_value 是证件号码 |
| skip_index | 否 | 是否跳过索引（纯技术/内部字段） | 是 — metadata 是 JSON 元数据，用户不会查 |

### 列补充的填写示例

```
table_name:    pmt_account
column_name:   account_type
enum_values:   1000=普通账户, 2000=LPSP, 2001=TPSP, 3000=RPSP

table_name:    pmt_account
column_name:   verification_status
display_name:  KYC/KYB认证状态
enum_values:   -1=拒绝, 0=默认/未认证, 1=已通过, 2=审核中

table_name:    pmt_account
column_name:   identification_value
sensitive:     是（证件号码）

table_name:    pmt_account
column_name:   metadata
skip_index:    是（JSON 元数据，用户不会直接查询）
```

## 材料 2：业务术语表

把业务里常用的名词/缩写/黑话整理出来。**这是对 SQL 准确率影响最大的一份材料**。

### 模板

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| term | 是 | 术语/名词 | KYC通过率 |
| definition | 是 | **用大白话解释是什么** | KYC认证通过的账户数占总账户数的比例 |
| sql_hint | 否 | **对应的 SQL 写法**（写了效果最好） | COUNT(CASE WHEN verification_status=1 THEN 1 END) / COUNT(*) |
| related_tables | 否 | 涉及哪些表 | pmt_account |
| related_columns | 否 | 涉及哪些列 | pmt_account.verification_status |

### 填写示例

```
term:             KYC通过率
definition:       KYC认证通过的账户数占总账户数的比例
sql_hint:         COUNT(CASE WHEN verification_status = 1 THEN 1 END) / COUNT(*)
related_tables:   pmt_account
related_columns:  pmt_account.verification_status

term:             活跃商户
definition:       account_status = 1 且 is_delete = 0 的账户
sql_hint:         account_status = 1 AND is_delete = 0
related_tables:   pmt_account
related_columns:  pmt_account.account_status, pmt_account.is_delete

term:             LPSP
definition:       License Payment Service Provider，持牌支付服务商
sql_hint:         account_type = 2000
related_tables:   pmt_account
related_columns:  pmt_account.account_type

term:             高风险商户
definition:       风险等级为 HIGH 或 VERY_HIGH 的商户
sql_hint:         risk_rating_level IN ('HIGH', 'VERY_HIGH')
related_tables:   pmt_account
related_columns:  pmt_account.risk_rating_level

term:             白标商户
definition:       开通了白标功能的商户
sql_hint:         white_label_status = 1
related_tables:   pmt_account
related_columns:  pmt_account.white_label_status

term:             新开户
definition:       最近30天内创建的账户
sql_hint:         create_time >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
related_tables:   pmt_account
related_columns:  pmt_account.create_time
```

### 容易遗漏的术语类型

请重点检查以下几类，业务方容易觉得"大家都懂"但机器不懂：

| 类型 | 举例 |
|------|------|
| **缩写/英文简称** | LPSP、TPSP、RPSP、MCC、KYC、KYB、GMV |
| **状态码含义** | verification_status=1 到底是什么意思 |
| **计算指标** | 通过率、转化率、退货率的分子分母分别是什么 |
| **区域/分组映射** | "华东区"包含哪些省份、"大客户"的定义门槛 |
| **时间默认值** | "最近"默认指多久、"上个月"是自然月还是滚动30天 |
| **过滤条件** | 查询时哪些条件是默认要带的（is_delete=0、status!=cancelled） |

## 材料 3：常见问题 & 标准 SQL

收集用户**真实会问的问题**，配上正确的 SQL。这些会作为 Few-shot 示例直接喂给 AI。

### 模板

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| question | 是 | **用户会怎么问**（用口语化的表达） | 目前有多少活跃商户 |
| sql | 是 | **正确的 SQL** | SELECT COUNT(*) ... |
| tables | 是 | 涉及哪些表 | pmt_account |
| difficulty | 否 | 难度：easy / medium / hard | easy |
| note | 否 | 备注 | 需要过滤 is_delete=0 |

### 填写示例

```
question:    目前有多少活跃商户
tables:      pmt_account
difficulty:  easy
sql: |
  SELECT COUNT(*) AS "活跃商户数"
  FROM dwd_banking.pmt_account
  WHERE account_status = 1
    AND is_delete = 0

question:    KYC认证通过率是多少
tables:      pmt_account
difficulty:  medium
sql: |
  SELECT
    COUNT(CASE WHEN verification_status = 1 THEN 1 END) AS "已通过",
    COUNT(*) AS "总数",
    ROUND(COUNT(CASE WHEN verification_status = 1 THEN 1 END) / COUNT(*) * 100, 2) AS "通过率(%)"
  FROM dwd_banking.pmt_account
  WHERE is_delete = 0

question:    各国家的商户数量分布
tables:      pmt_account
difficulty:  easy
sql: |
  SELECT country AS "国家", COUNT(*) AS "商户数"
  FROM dwd_banking.pmt_account
  WHERE is_delete = 0
  GROUP BY country
  ORDER BY COUNT(*) DESC
  LIMIT 100

question:    最近一个月新开户的企业有多少
tables:      pmt_account
difficulty:  medium
sql: |
  SELECT COUNT(*) AS "新开户企业数"
  FROM dwd_banking.pmt_account
  WHERE create_time >= DATE_SUB(CURDATE(), INTERVAL 30 DAY)
    AND legal_entity_type = 2000
    AND is_delete = 0

question:    各账户类型的商户占比
tables:      pmt_account
difficulty:  medium
sql: |
  SELECT
    CASE account_type
      WHEN 1000 THEN '普通账户'
      WHEN 2000 THEN 'LPSP'
      WHEN 2001 THEN 'TPSP'
      WHEN 3000 THEN 'RPSP'
      ELSE '其他'
    END AS "账户类型",
    COUNT(*) AS "数量",
    ROUND(COUNT(*) / SUM(COUNT(*)) OVER() * 100, 2) AS "占比(%)"
  FROM dwd_banking.pmt_account
  WHERE is_delete = 0
  GROUP BY account_type
  ORDER BY COUNT(*) DESC

question:    高风险商户有哪些，列出名称和国家
tables:      pmt_account
difficulty:  medium
sql: |
  SELECT
    account_name AS "商户名",
    legal_entity_name AS "企业名称",
    country AS "国家",
    risk_rating_level AS "风险等级",
    risk_score AS "风险评分"
  FROM dwd_banking.pmt_account
  WHERE risk_rating_level IN ('HIGH', 'VERY_HIGH')
    AND is_delete = 0
  ORDER BY risk_score DESC
  LIMIT 100
```

### 每张表建议覆盖的问题类型

| 类型 | 示例 | 每张表至少 |
|------|------|-----------|
| 简单计数 | "有多少XX" | 2 条 |
| 分组统计 | "按XX分布" | 2 条 |
| 比率/占比 | "XX率是多少" | 1 条 |
| 条件筛选 | "满足XX条件的有哪些" | 1 条 |
| 时间范围 | "最近XX天/上个月" | 1 条 |
| 多表 JOIN | "XX关联YY查询" | 1 条（如有关联表） |
| 排序/TOP N | "排名前10的XX" | 1 条 |

**每张表建议 8-15 条问题，覆盖以上类型。**

## 材料 4（可选）：表关联关系

如果多张表之间有 JOIN 关系，请整理出来。

### 模板

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| source_table | 是 | 左表 | pmt_account |
| source_column | 是 | 左表关联列 | customer_id |
| target_table | 是 | 右表 | dim_customer |
| target_column | 是 | 右表关联列 | customer_id |
| join_type | 否 | JOIN 方式 | LEFT JOIN |
| description | 否 | 说明 | 关联客户维度表获取客户详细信息 |

### 填写示例

```
source_table:    pmt_account
source_column:   customer_id
target_table:    dim_customer
target_column:   customer_id
join_type:       LEFT JOIN
description:     关联客户维度表获取客户详细信息

source_table:    pmt_transaction
source_column:   paid
target_table:    pmt_account
target_column:   paid
join_type:       INNER JOIN
description:     交易记录关联商户账户信息
```

## 交付格式

以下任一格式均可，系统都能解析：

| 格式 | 适合场景 |
|------|---------|
| **Excel**（推荐） | 最方便填写，一个 Sheet 一份材料 |
| **CSV** | 导出方便 |
| **YAML** | 技术同学偏好 |
| **飞书/Notion 表格** | 在线协作 |

> 不需要一次交齐。可以先给 3-5 张核心表，系统跑起来后再逐步补充。

## 优先级建议

如果时间紧，按以下优先级准备：

```
P0（必须有，否则系统跑不起来）
  ├── 表信息登记表：display_name + description + tags
  └── 常见问题 & 标准 SQL：每张表至少 5 条

P1（强烈建议，显著提升准确率）
  ├── 业务术语表：缩写、状态码含义、计算指标
  └── 列枚举值：enum_values 补全

P2（锦上添花）
  ├── 表关联关系
  ├── 列级补充（display_name、sensitive、skip_index）
  └── 每张表补到 10-15 条问题
```
