# Agent 镜像与运行

> 本文只描述 `data-agen` 执行面的镜像和 Compose 约定。整体发布顺序、Admin 联调及环境连接见[项目部署与运维](../../docs/deployment/部署与运维.md)。服务器、SSH、跳板和私钥以仓库外《环境资料.md》为准。

## 发布边界

- 本地构建 Linux AMD64 不可变镜像并推送到目标镜像仓库；
- Agent 服务器只拉取指定版本，不在服务器构建源码；
- 真实 `configs/config.yaml` 由服务器维护并只读挂载，不进入镜像或 Git；
- `model-cache` 和 `codex-home` 是持久卷，普通发布不得清理；
- 常规发布不自动重建索引。

## 服务器部署目录

实际目录以《环境资料.md》为准，其中至少需要：

```text
<AGENT_DEPLOY_DIR>/
├── docker-compose.yml
└── configs/
    └── config.yaml
```

`docker-compose.yml` 使用 `DATA_AGENT_IMAGE` 选择镜像，并将配置挂载到 `/etc/data-agen/config.yaml`。配置文件权限应为 `0600`。

## 构建与推送

```bash
cd data-agen

docker buildx build \
  --platform linux/amd64 \
  --load \
  --tag data-agen:<VERSION> \
  .

docker tag data-agen:<VERSION> <REGISTRY>/<REPOSITORY>:<VERSION>
docker push <REGISTRY>/<REPOSITORY>:<VERSION>
```

`<VERSION>` 应唯一且不可覆盖，例如“日期时间 + Git 短提交号”。不要用同名标签覆盖旧镜像。

## 拉取与启动

连接 Agent 节点并进入实际部署目录后执行：

```bash
export DATA_AGENT_IMAGE=<REGISTRY>/<REPOSITORY>:<VERSION>
docker pull "${DATA_AGENT_IMAGE}"
docker compose config
docker compose up -d --remove-orphans
docker compose ps
docker compose logs --tail=200 data-agen
curl -fsS http://127.0.0.1:9090/health
```

只有容器健康且响应中的 `ready=true`、`initialized=true` 才算发布完成。`CONFIG_SOURCE=mysql` 时还应确认返回的 Agent 与 `CONFIG_PROFILE` 一致。

## 配置与卷

当前 Compose 约定：

| 项目 | 作用 |
| --- | --- |
| `DATA_AGENT_IMAGE` | 不可变镜像地址 |
| `DATA_AGENT_PORT` | 宿主机映射端口，默认 9090 |
| `NL2SQL_CONFIG_FILE` | 容器内配置路径 |
| `configs/config.yaml` | MySQL、Milvus fallback、Token 和运行参数 |
| `data-agen_model-cache` | 本地模型缓存 |
| `data-agen_codex-home` | Codex 认证状态 |

生产配置参考 `configs/config.example.yaml` 创建；不要把示例占位符直接用于目标环境。

## 索引操作

- 普通代码发布保持 `REBUILD_INDEX_ON_STARTUP=false`；
- 语义变更优先由 Admin 索引协调器按脏模块同步；
- 只有 Embedding/维度变化、索引损坏或明确运维要求时才执行全量重建；
- 重建前确认目标 Agent、Milvus database、Collection 后缀和 Embedding 维度。

## 恢复

将 `DATA_AGENT_IMAGE` 指向上一已验证的不可变版本并重新执行 `docker compose up -d --remove-orphans`。恢复镜像不回滚 MySQL 语义版本或 Milvus 索引版本，涉及协议或索引变更时必须先确认兼容关系。
